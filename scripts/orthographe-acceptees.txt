# Les signalements relus et acceptés.
#
# Une ligne par cas : `chemin | RÈGLE | texte signalé`. La ligne du fichier n'y est pas, parce
# qu'elle bouge à chaque réécriture ; le triplet, lui, tient.
#
# **Pourquoi cette liste plutôt que des règles coupées.** Couper `ACCORD_SUJET_VERBE` laisserait
# passer un vrai désaccord ailleurs. Ici la règle reste allumée : seuls les cas écrits ci-dessous
# sont acceptés, et un cas nouveau fait tomber la commande.
#
# Chacun a été lu dans son fichier avant d'entrer ici. Ils se rangent en six familles :
#
#   1. **Un bout de code au milieu d'une phrase.** Il est remplacé par le substitut « ceci », qui
#      est masculin singulier ; « les `package.json` ne contiennent » devient « ceci ne contiennent »,
#      et l'accord se plaint. Le texte, lui, est juste.
#   2. **Un tableau.** Une cellule n'est pas une phrase : elle n'a souvent ni sujet ni verbe.
#      Les maquettes de `docs/maquettes/`, qui en étaient pleines, ne sont plus relues : elles
#      décrivent les écrans pour celui qui les construit, et aucun utilisateur ne les lit.
#   3. **Une notation technique** : `-120..240`, `<=`, `webcal:`, un nom de colonne, un sigle.
#   4. **Un abrégé de jour ou de mois** : `Sa`, `mer`, `sab`, `min`. Ce sont les formes courtes des
#      écrans, et elles sont voulues.
#   5. **Un mot composé allemand** que le dictionnaire suisse ne porte pas : `Kalenderabo`,
#      `https-Adresse`. Ils sont corrects et compris.
#   6. **Une suggestion de vocalisation en arabe.** LanguageTool propose d'ajouter des diacritiques ;
#      les écrans publics n'en mettent pas, par choix (ADR 0007).
#
# Retirer une ligne d'ici, c'est redemander à la voir. Ajouter une ligne demande d'avoir lu le texte.
